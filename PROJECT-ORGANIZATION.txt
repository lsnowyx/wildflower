WILDFLOWER - CURRENT PROJECT ORGANIZATION
=========================================

Snapshot date: 2026-08-06
Branch: codex-refactor


1. SOLUTION OVERVIEW
--------------------

The solution file is:

    wildflower.sln

It currently contains three projects:

    1. wildflower
       Legacy, functional Windows Forms application.

    2. wildflowerBackend
       Standalone backend class-library project containing copied Models and
       Services from the legacy project.

    3. wildflowerFrontend
       Newly scaffolded .NET MAUI application. It is still the default template
       and is not connected to the backend.

Important current detail:

    There are no ProjectReference entries between these projects. They are in
    the same solution, but they currently compile independently.

6. CURRENT BACKEND RESPONSIBILITIES
-----------------------------------

Models:

    TrackInfo
        File path, title, artist, and derived display name.

    PlaylistInfo
        Playlist id, physical playlist directory, music folder, and derived
        persistence-file paths.

    PlaybackState
        Persisted current index and BASS byte position.

    PlaybackProgress
        Millisecond and BASS-byte progress values.

    PlayerSessionSnapshot
        Read model for frontend state, current track, playback state, progress,
        volume, loop mode, and capability flags.

    PlayerStatus / LoopMode
        Playback and loop enums.

Services:

    PlayerSessionService
        Coordinates playlist loading, playback, track selection, persistence,
        shuffle, refresh, automatic advancement, temporary playback, snapshots,
        and session events.

    BassPlaybackEngine
        Wraps the BASS playback API and stream handle.

    PlaylistService / FilePlaylistStorage
        Manage playlists and the on-disk persistence layout.

    MusicLibraryScanner
        Scans a music folder for supported audio files.

    TagLibMetadataService
        Loads title and artist metadata with filename fallback.

    SearchService
        Searches filenames and metadata.

    AudioDeviceWatcher
        Watches the Windows default render/console device through NAudio.


7. PERSISTED DATA ORGANIZATION
------------------------------

Runtime playlist data remains outside the repository at:

    %APPDATA%\.wildflower\playlists\

Layout:

    lastUsed.txt
    0\
        musicFolderPath.txt
        playlist.txt
        state.txt
    1\
        musicFolderPath.txt
        playlist.txt
        state.txt
    ...

Contract:

    lastUsed.txt
        Active numbered playlist id.

    musicFolderPath.txt
        Selected music-library folder path.

    playlist.txt
        Track filenames, not absolute paths.

    state.txt
        Exactly: index|BASS byte position

Temporary playback restoration is implemented by re-reading the active
playlist's persisted state.txt through the backend storage service.


8. CURRENT RUNTIME FLOW
-----------------------

Functional legacy flow:

    Program.cs
        -> Form1
        -> constructs concrete backend services
        -> uses IPlayerSessionService for playback/session commands
        -> uses WinForms timers for progress, advancement, and 30-second saves
        -> uses WinForms folder picker and controls

Current MAUI flow:

    Windows/Android/iOS/MacCatalyst platform entry point
        -> MauiProgram
        -> App
        -> AppShell
        -> MainPage default click-counter template

There is currently no flow from wildflowerFrontend to wildflowerBackend.


9. CURRENT SEPARATION STATUS
----------------------------

Logical separation:

    The legacy code has UI-neutral models and service interfaces, and Form1
    mostly talks to PlayerSessionService instead of directly using BASS or
    playlist files.

Physical separation:

    A backend class-library project now exists, but extraction is incomplete.
    The legacy project still compiles its own complete backend copy, while the
    class library compiles a second copy. Neither frontend references the class
    library.

MAUI status:

    The MAUI project is a scaffold only. Backend dependency injection, folder
    picking, player view models/views, timers, lifecycle saving, BASS native
    deployment, and audio-device watcher integration have not been implemented.
